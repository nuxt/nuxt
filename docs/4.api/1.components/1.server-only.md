## Usage

`<ServerOnly>` renders its default slot on the server and keeps that HTML as a static vnode on the client. The slot does not run again during hydration, so a value captured while rendering (for example `{{ new Date() }}`) stays the same in the browser.

It is a universal component, not a server component. The slot belongs to the parent. When that parent is also universal, the slot is not serialized into an island request, so wrapping the slot in a server component would leave the server with nothing to render.

On client-side navigation there is no server HTML to keep, and the slot is not rendered again. The wrapper is empty. If the content itself must be rendered on the server during navigation, put it in a [server component](/docs/directory-structure/app/components#server-components) (`.server.vue`).

`<ServerOnly>` is not a security boundary. The slot is part of the parent page, and that page's code is still sent to the client. Do not put secrets or private data in the slot.

```vue
<template>
  <footer>
    <ServerOnly>
      Generated at {{ new Date().toISOString() }}
    </ServerOnly>
  </footer>
</template>
```

## Comparison with `<ClientOnly>`

| | `<ServerOnly>` | `<ClientOnly>` |
| --- | --- | --- |
| Slot runs | During server render | After the component mounts in the browser |
| After hydration | Server HTML stays as-is | Slot replaces the placeholder |
| Client-side navigation | Wrapper is empty | Slot runs in the browser |

## Props

`<ServerOnly>` does not accept any props. Attributes on the component are passed to the wrapper element.

```vue
<template>
  <ServerOnly
    class="timestamp"
    data-testid="build-time"
  >
    Built at {{ buildTime }}
  </ServerOnly>
</template>
```

## Slots

- `default`: content rendered on the server and kept as static HTML on the client.
