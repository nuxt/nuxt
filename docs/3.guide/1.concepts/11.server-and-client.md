Nuxt applications run in more than one environment. Code in your pages, layouts, and components can execute on the **server** during SSR, again on the **client** during hydration, and only in the **browser** after mount.

Understanding these phases helps you avoid hydration mismatches and place browser-only logic in the right spot.

Learn about universal rendering and hydration.
::

## Execution Phases

| Phase | Where it runs | What happens |
| --- | --- | --- |
| **SSR** | Server (Node.js / Nitro) | Nuxt renders HTML for the initial request |
| **Hydration** | Browser | Vue attaches to existing HTML and makes the page interactive |
| **Post-mount** | Browser only | Event handlers, `onMounted` callbacks, and client-only APIs run freely |

During SSR and hydration, the HTML the server sent must match what Vue expects on the client. Mismatches produce [hydration warnings](/docs/4.x/guide/best-practices/hydration) in development.

## What Runs Where

The table below summarizes typical Nuxt building blocks. Exceptions exist (for example, client-only plugins or `.client.vue` components), but this is a useful default mental model.

| Building block | Server (SSR) | Client (hydration) | Browser (after mount) |
| --- | --- | --- | --- |
| [Pages](/docs/4.x/directory-structure/app/pages) | Yes | Yes | Yes |
| [Layouts](/docs/4.x/directory-structure/app/layouts) | Yes | Yes | Yes |
| [Route middleware](/docs/4.x/directory-structure/app/middleware) | Yes | Yes | Yes |
| [Plugins](/docs/4.x/directory-structure/app/plugins) | Depends on mode | Depends on mode | Depends on mode |
| [Composables](/docs/4.x/directory-structure/app/composables) | When called from universal code | When called from universal code | Always when called |
| `<script setup>` top level | Yes | Yes | Yes |
| `onMounted` and other mount hooks | No | No | Yes |
| [Server components](/docs/4.x/guide/concepts/server-components) | Yes | No | No |
| [`.client.vue` components](/docs/4.x/directory-structure/app/components#client-components) | No | No | Yes (after mount) |
| [`<ClientOnly>`](/docs/4.x/api/components/client-only) slot content | No | No | Yes (after mount) |
| [`<DevOnly>`](/docs/4.x/api/components/dev-only) content | Dev server only | Dev server only | Dev server only |

### Setup vs Mount Hooks

Code in `<script setup>` runs during both SSR and hydration when the component is universal. That is why reading `localStorage` or `window` in setup causes hydration mismatches.

Use [`onMounted`](https://vuejs.org/api/composition-api-lifecycle#onmounted) (or [`import.meta.client`](/docs/4.x/api/advanced/import-meta) guards) for logic that must run only after the component is active in the browser.

## Detecting the Current Environment

Use [`import.meta`](/docs/4.x/api/advanced/import-meta) flags to branch code at build time or runtime:

| Flag | Meaning |
| --- | --- |
| `import.meta.server` | Code runs on the server (SSR, prerender, or Nitro) |
| `import.meta.client` | Code runs in the browser |
| `import.meta.dev` | Nuxt dev server is running |
| `import.meta.prerender` | Page is being prerendered at build time |

```vue [app/components/UserAgent.client.vue]
<script setup lang="ts">
const userAgent = ref('')

if (import.meta.client) {
  userAgent.value = navigator.userAgent
}
</script>

<template>
  <p>{{ userAgent }}</p>
</template>
```

::note
`process.client`, `process.server`, and related `process.*` flags were soft-deprecated in Nuxt 3.12. Prefer `import.meta.client` and `import.meta.server`. With `future.compatibilityVersion: 5`, Nuxt no longer augments `NodeJS.Process` with those properties.
::

## Checking Hydration State

[`useNuxtApp()`](/docs/4.x/api/composables/use-nuxt-app) exposes `isHydrating`, a boolean that is `true` while the client is hydrating SSR output.

Use it when you need to skip client-side logic during the hydration pass:

```ts [app/middleware/analytics.global.ts]
export default defineNuxtRouteMiddleware(() => {
  const nuxtApp = useNuxtApp()

  if (import.meta.client && nuxtApp.isHydrating && nuxtApp.payload.serverRendered) {
    return
  }

  // Run analytics after hydration completes
})
```

## Client-Only and Dev-Only Tools

When server and client output cannot match, use the tool that fits:

- [`<ClientOnly>`](/docs/4.x/api/components/client-only) — skip SSR for a subtree and optionally render a `#fallback` placeholder
- [`.client.vue` suffix](/docs/4.x/directory-structure/app/components#client-components) — entire components that never run on the server
- [`<DevOnly>`](/docs/4.x/api/components/dev-only) — debug UI removed from production builds

::read-more{to="/docs/4.x/guide/best-practices/hydration#choosing-a-client-only-strategy"}

## In Summary

1. **Assume universal code runs twice** — on the server and during client hydration — unless you opt into client-only patterns
2. **Use `import.meta.client` / `import.meta.server`** instead of deprecated `process.client` / `process.server`
3. **Defer browser APIs** to `onMounted` or client-only components
4. **Check `nuxtApp.isHydrating`** when you need to avoid running logic during the hydration pass
