[WebMCP](https://webmachinelearning.github.io/webmcp/) is a proposed browser API that lets a page offer tools to AI agents running in the browser, so an agent can add something to a cart or submit a form without guessing which button to click. Nuxt can turn the actions your templates already bind into WebMCP tools.

::important
This is an experimental feature, built on an API that is still being designed. Tools register only in browsers that support WebMCP, such as Chrome with `chrome://flags/#enable-webmcp-testing` turned on, or started with `--enable-features=WebMCP`.
::

Enable it in your `nuxt.config`:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    webmcp: true,
  },
})
```

## Tools from Templates

Tag a function with `@tool` in its JSDoc and bind it to `@click` or `@submit` on an element, or to an event on a component. Nuxt registers a tool named after the function, described by the JSDoc summary:

```vue [app/pages/index.vue]
<script setup lang="ts">
const { data: products } = await useFetch('/api/products')
const cart = useCart()

/**
 * Add one of a product to the cart. Use when the user wants to buy something.
 * @tool
 */
function addToCart (sku: string) {
  cart.value.push(sku)
}
</script>

<template>
  <ul>
    <li
      v-for="product in products"
      :key="product.sku"
    >
      {{ product.name }}
      <button
        :disabled="!product.inStock"
        @click="addToCart(product.sku)"
      >
        Add
      </button>
    </li>
  </ul>
</template>
```

This registers an `add_to_cart` tool, and:

- the arguments come from the template, so the agent cannot pass a SKU that is not on the page;
- inside a `v-for`, the agent picks an item by its `:key` as `target`, and a shared `list_targets` tool lists the items on screen with their text;
- `:disabled` controls whether the tool, or one of its targets, can run;
- a call runs the bound expression, and its return value is the tool result.

Write descriptions for the agent: say what the tool does for the user and when to use it, and leave implementation details out.

Flags after `@tool` describe the action:

| Flag | Meaning |
| --- | --- |
| `readonly` | The tool only reads, so an agent can call it freely. |
| `consequential` | The tool has effects that are hard to undo, so the browser or agent may ask the user first. |
| `confirm` | The user must complete the action. A call highlights the control (or fills in the form) and returns `status: "requires_user_action"` instead of running it. |

```ts
/**
 * Place the order for everything in the cart. Use when the user is ready to pay.
 * @tool consequential
 */
function checkout () {}
```

## Forms

A `@tool` function bound to `@submit` becomes a form tool. Its input is the form's `v-model` bindings, and a call writes them, then submits the form, so your own validation and submit handler run as they would for the user. Fields whose `v-model` reads a `v-for` or slot variable declared inside the form are not part of the input.

Pass a [Standard Schema](https://standardschema.dev) (such as Zod, Valibot or ArkType) with `@input`, or bind it to the form as `:schema`, to validate the input. A schema that implements Standard JSON Schema, such as a Zod schema, or a Valibot schema wrapped in `toStandardJsonSchema()` from `@valibot/to-json-schema`, also describes the input to the agent. Otherwise, types come from the current values and the native controls. Labels become descriptions, and current values become defaults.

```vue [app/pages/contact.vue]
<script setup lang="ts">
import { z } from 'zod'

const contactSchema = z.object({
  email: z.email(),
  message: z.string().min(5),
})
const form = reactive({ email: '', message: '' })

/**
 * Send a message to the shop. Use when the user has a question about an order.
 * @tool
 * @input contactSchema
 */
async function sendMessage () {
  await $fetch('/api/contact', { method: 'POST', body: form })
  return 'Sent.'
}
</script>

<template>
  <form @submit.prevent="sendMessage">
    <label>Email <input
      v-model="form.email"
      type="email"
    ></label>
    <label>Message <textarea v-model="form.message" /></label>
    <button type="submit">
      Send
    </button>
  </form>
</template>
```

Input is validated before anything is written, so a rejected call leaves the form as it was.

## Tools from Code

For tools that do not map to one control, define a tool with `defineAgentTool()` and offer it while a component is mounted with `useAgentTool()`:

```vue [app/components/ProductSearch.vue]
<script setup lang="ts">
import { z } from 'zod'

const searchProducts = defineAgentTool({
  name: 'search_products',
  description: 'Find products by name. Use when the user asks what is for sale.',
  input: z.object({ query: z.string() }),
  annotations: { readOnlyHint: true },
  execute: ({ query }, { signal }) => $fetch('/api/products', { query: { q: query }, signal }),
})

useAgentTool(searchProducts)
</script>
```

`input` validates each call, and describes the tool's parameters when the schema implements Standard JSON Schema. For other schemas, describe the parameters with `inputSchema`.

Pass `targets` (with `key` and `label`) to let the agent choose between items, and `enabled` to make the tool unavailable without unregistering it.

## Showing What the Agent Does

`useAgentActivity()` returns the tool calls in progress, so you can show the user what an agent is doing and let them stop it. Stopping a call aborts the `signal` passed to the tool, and the agent receives a result asking it not to retry.

```vue [app/components/AgentStatus.vue]
<script setup lang="ts">
const { current, stop } = useAgentActivity()
</script>

<template>
  <p v-if="current">
    {{ current.message }}
    <button @click="stop">
      Stop
    </button>
  </p>
</template>
```

## Navigation

Nuxt also registers a `navigate` tool listing your app's pages, so an agent can reach actions on other pages. Tools are swapped when the page changes. Disable it with `navigate: false`:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    webmcp: { navigate: false },
  },
})
```

## Development

Nuxt warns at build time about bindings that cannot become tools (such as handlers that wrap a `@tool` function, or a `v-for` keyed by its index), descriptions that do not follow the [WebMCP tool design guidance](https://github.com/GoogleChromeLabs/webmcp-tools), and form fields without a label. In development, it also warns about tools and results that are longer than agents handle well.

While `nuxt dev` runs with the Vite builder, every tool your pages offer as you browse is written to `.nuxt/webmcp/schema.json`, with the tools seen on each page. This works in any browser. You can use it with [`webmcp-evals`](https://github.com/GoogleChromeLabs/webmcp-tools/tree/main/webmcp-evals) to check that a model picks the right tools. Set `schema` to write it somewhere else, or `false` to turn it off:

```ts twoslash [nuxt.config.ts]
export default defineNuxtConfig({
  experimental: {
    webmcp: { schema: 'webmcp.schema.json' },
  },
})
```
