[eve](https://eve.dev) is a framework for building durable AI agents. Its `eve/nuxt` module runs a Nuxt app and an eve agent as a single project, from one dev server and one deployment.

## Installation

eve requires Node.js 24 or newer. Install it in your Nuxt project:

```bash [Terminal]
npm install eve ai zod
```

Then register the module:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['eve/nuxt'],
})
```

The module looks for an `agent/` directory in your project root. A minimal agent only needs an `agent/instructions.md` file. See [Agent Files](https://eve.dev/docs/reference/agent-files) for everything an agent can contain.

## Usage

The module auto-imports the `useEveAgent` composable. It connects to the agent's routes on the same origin, so there is no CORS or base URL to configure:

```vue [app/app.vue]
<script setup lang="ts">
const { messages, status, send } = useEveAgent()

const message = ref('')

async function handleSubmit () {
  const text = message.value.trim()
  if (!text || status.value !== 'idle') {
    return
  }
  message.value = ''
  await send(text)
}
</script>

<template>
  <div
    v-for="item in messages"
    :key="item.id"
  >
    <template
      v-for="(part, index) in item.parts"
      :key="index"
    >
      <p v-if="part.type === 'text'">
        {{ item.role }}: {{ part.text }}
      </p>
    </template>
  </div>
  <form @submit.prevent="handleSubmit">
    <input v-model="message">
    <button type="submit">
      Send
    </button>
  </form>
</template>
```

During development, `nuxt dev` also starts the eve dev server and proxies its routes through Nuxt. On Vercel, the app and the agent deploy as one project.

::warning
eve rejects browser requests in production by default. Configure an auth policy before deploying. See [Authentication](https://eve.dev/docs/guides/auth-and-route-protection).
::
