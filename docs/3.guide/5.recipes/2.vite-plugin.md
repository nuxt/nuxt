While Nuxt modules offer extensive functionality, sometimes a specific Vite plugin might meet your needs more directly.

First, we need to install the Vite plugin, for our example, we'll use `@rollup/plugin-yaml`:

::code-group{sync="pm"}

  ```bash [npm]
  npm install @rollup/plugin-yaml
  ```

  ```bash [yarn]
  yarn add @rollup/plugin-yaml
  ```

  ```bash [pnpm]
  pnpm add @rollup/plugin-yaml
  ```

  ```bash [bun]
  bun add @rollup/plugin-yaml
  ```

  ```bash [deno]
  deno add npm:@rollup/plugin-yaml
  ```

::

Next, we need to import and add it to our [`nuxt.config.ts`](/docs/4.x/directory-structure/nuxt-config) file:

```ts [nuxt.config.ts]
import yaml from '@rollup/plugin-yaml'

export default defineNuxtConfig({
  vite: {
    plugins: [
      yaml(),
    ],
  },
})
```

Now we installed and configured our Vite plugin, we can start using YAML files directly in our project.

## Dependency Optimization and Transpilation

Vite [pre-bundles dependencies](https://vite.dev/guide/dep-pre-bundling) during development. Nuxt configures this automatically in most cases, but packages with unusual module formats or deep imports may need an explicit hint:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  vite: {
    optimizeDeps: {
      // Pre-bundle a dependency that Vite cannot discover automatically.
      include: ['my-dependency'],
      // Leave a dependency as source for Vite to process directly.
      exclude: ['my-linked-dependency'],
    },
  },
})
```

Use these options for different purposes:

- `vite.optimizeDeps.include` forces a dependency into Vite's development-only pre-bundle. This can help dependencies that are not directly discoverable, such as a CommonJS dependency reached through another dependency.
- `vite.optimizeDeps.exclude` skips the development pre-bundle. This can help linked packages that should be transformed as source, or packages that are incompatible with pre-bundling.
- `build.transpile` asks Nuxt's build pipeline to transform matching files in both development and production. Use it when a dependency contains syntax that the target environment cannot run, or Nuxt composables that require a compile-time transform.

For example, transpiling a library is configured separately from Vite dependency optimization:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  build: {
    transpile: ['my-library'],
  },
})
```

::note
Dependency optimization only affects development startup and module loading; it does not change the production bundle. Avoid adding dependencies to `include`, `exclude`, or `transpile` unless you have a specific resolution or transformation problem.
::

For example, we can have a `config.yaml` that stores configuration data and import this data in our Nuxt components:

::code-group

```yaml [data/hello.yaml]
greeting: "Hello, Nuxt with Vite!"
```

```vue [app/components/Hello.vue]
<script setup>
import config from '~/data/hello.yaml'
</script>

<template>
  <h1>{{ config.greeting }}</h1>
</template>
```

::

## Using Vite Plugins in Nuxt Modules

If you're developing a Nuxt module and need to add Vite plugins, you should use the [`addVitePlugin`](/docs/4.x/api/kit/builder#addviteplugin) utility:

```ts [modules/my-module.ts]
import { addVitePlugin, defineNuxtModule } from '@nuxt/kit'
import yaml from '@rollup/plugin-yaml'

export default defineNuxtModule({
  setup () {
    addVitePlugin(yaml())
  },
})
```

For environment-specific plugins in Nuxt 5+, use the `applyToEnvironment()` method:

```ts [modules/my-module.ts]
import { addVitePlugin, defineNuxtModule } from '@nuxt/kit'

export default defineNuxtModule({
  setup () {
    addVitePlugin(() => ({
      name: 'my-client-plugin',
      applyToEnvironment (environment) {
        return environment.name === 'client'
      },
      // Plugin configuration
    }))
  },
})
```

::important
If you're writing code that needs to access resolved Vite configuration, you should use the `config` and `configResolved` hooks _within_ your Vite plugin, rather than using Nuxt's `vite:extend`, `vite:extendConfig` and `vite:configResolved`.
::

Read more about `addVitePlugin` in the Nuxt Kit documentation.
::
