# E8008

With `experimental.ssrStreaming` enabled, the HTML shell (including `<head>`) is flushed before the route finishes rendering. Head tags registered synchronously during setup are captured before the shell flushes and render into `<head>` as usual. Head tags registered *after* the shell is on the wire (typically via `useHead` or `useSeoMeta` after an `await` in `<script setup>`, or inside a nested `<Suspense>` boundary) cannot be inserted into the already-sent `<head>`. They are delivered as inline scripts that patch the DOM on the client instead.

For browsers and for indexing crawlers (which receive buffered, non-streamed HTML by default via `botRegex`) this is invisible. But clients that do not execute JavaScript and fall outside the bot regex (some crawlers, link unfurlers, `curl`) will not see these tags at all. If they include SEO-critical content such as canonical links, JSON-LD, or social meta tags, that content may be missing from the served HTML.

This warning is emitted during development when a streamed route delivers head tags as client-side patches.

## Resolution

Move SEO-critical `useHead`/`useSeoMeta` calls so they run before the shell flushes:

- Call them synchronously in `<script setup>`, before any `await`.
- Or register them in a plugin, which always runs before rendering begins.

If the values genuinely depend on async data, either restructure so the data is available synchronously (e.g. from route params or payload), or opt the route out of streaming:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  routeRules: {
    '/needs-full-head/**': { streaming: false },
  },
})
```
