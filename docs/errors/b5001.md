# B5001

No `compatibilityDate` is set in your Nuxt configuration. Nuxt uses this date to decide which behavior defaults to apply, so your project stays stable across Nuxt and Nitro updates instead of silently picking up new defaults.

## Resolution

Add `compatibilityDate` to your `nuxt.config`, using today's date so you opt in to the current defaults:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // use the current date, e.g. the day you add this line
  compatibilityDate: 'YYYY-MM-DD',
})
```

If you use [layers](/docs/4.x/getting-started/layers) and keep shared Nuxt options in a layer config (for example `common/nuxt.config.ts`), add `compatibilityDate` there instead of the project root. In development, when more than one local config is present, the `NUXT_B5001` fix text lists those files so you can pick the right one.
