# B5001

No `compatibilityDate` is set in your Nuxt configuration. Nuxt uses this date to decide which behavior defaults to apply, so your project stays stable across Nuxt and Nitro updates instead of silently picking up new defaults.

## Resolution

Add `compatibilityDate` to your `nuxt.config`, using today's date so you opt in to the current defaults:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // use the current date, e.g. the day you add this line
  compatibilityDate: 'YYYY-MM-DD',
})
```

In interactive development, Nuxt can offer to write this for you. If you use [layers](/docs/4.x/getting-started/layers) and have more than one local config (outside `node_modules`), you can choose which file to update. Prefer the layer where you keep shared Nuxt options (for example `common/nuxt.config.ts`) when that is how your project is structured.
